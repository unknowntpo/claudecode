# 交接文件：健身女性背面走路動畫

> 狀態：**暫停中**（2026-11-20）
> 分支：`claude/sharp-einstein-bqt8qh`

## 1. 需求

- 參考：使用者提供的角色設定圖（短鮑伯頭、深灰運動內衣、膚色系高腰緊身褲、白色運動鞋、健美體態），以及 Threads 上「GPT-6.2 Astra 用程式做出雨中台北」的貼文。
- 目標：用**寫程式**的方式為這位健身女性建模，做一支 **10 秒、背面視角的走路動畫**，要彰顯女性的**力與美**。
- 原則：比照那篇貼文，不用 AI 影片生成工具，而是由程式產生畫面（與聲音）。

## 2. 目前做到哪裡（第一版：SDF 程式建模）

| 檔案 | 說明 |
|---|---|
| `index.html` | 單一網頁，WebGL2 即時播放。用瀏覽器打開即可，左下角按鈕會連程式合成的音效一起播 |
| `render.mjs` | Playwright 無頭 Chromium 逐格截圖，再用 ffmpeg 合成 MP4。用法：`node render.mjs 540 960 30`；測試單格：`node render.mjs 405 720 30 0.3,5,9.5` |
| `README.md` | 技術說明 |

技術組成：
- **步態**：用 JS 寫髖、膝、腳掌的關鍵影格 + 正向運動學。骨盆有旋轉、側傾、重心移動，肩膀反向旋轉，手臂與對側腿同步擺。以「最低接觸點貼地不動」反推前進量，所以腳不會滑步。
- **身體**：約 50 個圓錐膠囊和橢球，按肌群擺放，用 smooth-min 融合；脊椎溝用平滑減法挖出。服裝依身體局部座標在 shader 裡上色。
- **渲染**：GLSL ray marching。逆光晨光加左側掠射主光，有軟陰影、AO、濕地反射、路燈和天際線。
- **聲音**：Web Audio 合成腳步聲、車流底噪、鳥叫和低頻氛圍；用 OfflineAudioContext 輸出 WAV。

## 3. 為什麼暫停：使用者回饋

> 「做得完全不像是一個人，比 AI 生成圖片還慘。」

這個判斷成立。用幾何基本形拼人體，上限是「風格化人偶」；皮膚、布料、頭髮的質感和比例都無法接近照片。人體又是最容易被看出破綻的題材。對照：雨中台北那支影片裡沒有任何人，只有建築和物件。

**結論：放棄繼續加強 SDF 版本**，保留它當技術示範和對照組。

另外，完整影片**沒有算完**：本機沒有 GPU，靠 SwiftShader 用 CPU 算，4 個 worker 並行時每格約 25–40 秒，300 格只算了 30 格就暫停。`out/` 不在版控裡。

## 4. 下一步：方案 A（使用者已選定的方向）

**用真實人體模型 + 動作捕捉資料 + Blender Python 腳本渲染。** 全程仍是寫程式，但用現成的開源素材。

| 項目 | 候選 | 待確認 |
|---|---|---|
| 人體模型 | MakeHuman / MPFB2（MakeHuman 的 Blender 外掛）。身形用 macro 參數調：性別、年齡、肌肉量、體重、比例 | 素材授權條款（據了解內建素材採 CC0，要親自確認）；能否從這台機器下載 |
| 頭髮、服裝 | MakeHuman 社群素材中的鮑伯頭、運動內衣、緊身褲；不合適就在 Blender 裡用腳本建或修 | 是否有合適的素材 |
| 走路動作 | CMU Motion Capture Database 的走路片段（BVH 版本），重定向到 MakeHuman 骨架 | 授權條款；重定向品質 |
| 渲染 | Blender Cycles：皮膚 SSS、頭髮 shader、布料。用 `bpy`（PyPI 套件）或 Blender 執行檔加 `--background --python` | `bpy` 套件要對應特定 Python 版本，本機是 **Python 3.13**，可能要另外裝 Blender 執行檔 |
| 鏡頭與燈光 | 沿用第一版的設計：背面、低角度慢慢推近、逆光輪廓光加側面掠射光 | — |
| 聲音 | 可直接重用 `index.html` 裡的 Web Audio 音效。腳步時間要改成從 mocap 的觸地時刻取 | — |

建議步驟：
1. **可行性驗證**：先確認能安裝 Blender、能下載 MakeHuman 素材和 mocap，網路有沒有被擋。被擋的話，要使用者在環境設定裡開放對應網域，或在自己電腦上跑。
2. 用腳本建出角色：調 macro 參數做健身體態，加上頭髮和服裝，再和角色設定圖比對。
3. 匯入走路 mocap，重定向，裁出 10 秒，調整步幅和速度。
4. 設定燈光、鏡頭，渲染低解析度預覽給使用者看，**通過後**才算正式版。
5. 正式渲染，合成音效，輸出 MP4。

## 5. 主要風險

- **算力**：沒有 GPU 的話，Cycles 用 CPU 算 300 格（每格要幾十個以上的取樣）可能要好幾個小時。可以考慮：用 EEVEE（但無頭環境可能需要 GPU 或 OpenGL）、降低解析度和取樣數加降噪，或是在使用者有 GPU 的電腦上跑。
- **真實度上限**：方案 A 預期能到「遊戲或 CG 角色」的等級，仍不是照片等級。要照片等級只能用 AI 影片生成（方案 C），但這不符合「用程式做」的前提。開工前要先跟使用者對齊這個期待。
- **內容分寸**：使用者要求的是「力與美」。呈現重點放在肌肉線條、步態和光影；服裝保持完整、有明顯的布料質感，避免看起來像裸色。

## 6. 更新：方案 B「仿生機器人版」（暫停於第 2 輪審查）

參考 [Nyxera0x/cutaway](https://github.com/Nyxera0x/cutaway) 的做法，改做白殼仿生健身女性，放在 `robot/`。

- **目前狀態**：靜態圖已到第 2 輪審查點，等使用者確認，**還沒開始做走路影片**。預覽圖在 `robot/preview/`。
- **怎麼跑**：
  ```bash
  cd robot && npm install
  node build.mjs                                      # → dist/index.html
  MASK=1 node still.mjs back,walk,upper,walkLow 900 1600
  python3 measure.py <參考圖背面裁切.png> out/back.png   # 比例與深色佔比
  ```
- **方法**：`robot/CHECKLIST.md` 是從參考圖量出的比例和 12 條檢查清單。每個部位是連續的解剖曲面，切成外殼片、留細縫，機構只從窗口露出。量測結果與參考圖相差都在 0.02 內（小腿略細），深色佔比是參考圖的 1.04 倍。
- **已知待修**：臀部像一整塊大板、肩頭還有點像護肩、背部肌肉大多被運動內衣蓋住。
- **待使用者決定**：配色方向（白加沙色 / 白加綠 / 膚色），以及要先修上述三點，還是直接做 10 秒背面走路影片。
- **做影片要準備的事**：`robot.js` 已經有 `walkState(t)` 步態和兩段式液壓缸。還需要沿用第一版的「接觸點不滑步」積分來算前進量、設計鏡頭路徑、逐格渲染，再搭配 Web Audio 音效。沒有 GPU 時每格約 20 秒，10 秒 30fps 約需 1.5 到 2 小時。
